Troubleshooting

Common issues while configuring, running or changing cloud-mask-composite-images, and how to resolve them.

Configuration & connections

A data source connection fails or times out

Check the server URL and credentials in the connection, and that you can sign in to the same server in a browser with them. The account needs API access to the data the workflow asks for.

Earth Engine authentication or permission errors

The Earth Engine data source needs a service account (or user) registered for Earth Engine, with a Cloud project that has the Earth Engine API enabled. Check that the connection works in Studio before running.

Every step is skipped

The area-of-interest file loaded with no rows. Check the path and that the file has features. For a .gpkg with several layers, the first layer is read.

Building the composite

No Sentinel-2 scenes under 60.0% cloud cover for …

No scene over the area in the time range passed the cloud threshold. Raise Cloud Threshold (cloudy pixels are still masked out), widen the time range, or switch sensor. Sentinel-2 surface reflectance only covers 2017 onward. Use Landsat for earlier years.

Select at least one band or spectral index to export.

Both Bands and Indices are empty. Select at least one.

The map has holes or patchy gaps inside the area

Those pixels had no clear observation (valid_count = 0): every scene was cloudy there. Show valid_count on the map to see where coverage is thin. Then widen the time range or raise the cloud threshold.

Stripes across a Landsat composite

Landsat 7 scan-line gaps (after May 2003). Widen the time range so other scenes fill them, or use a period with Landsat 8/9 (2013 onward).

Speckles or bright/dark blotches remain

Clouds, haze or shadows the quality band missed. Use the median reducer (max favours bright clouds; min favours shadows) and a longer time range so each pixel has more observations.

The run is slow, or computePixels times out or hits a quota

The download covers the area's whole bounding box at 10 m (Sentinel-2) or 30 m (Landsat). Use a smaller or more compact area, or Landsat, which has 9× fewer pixels. Rerun after a quota error. The file is rewritten from the start.

The map

Band(s) ['…'] not in …tif. Available: […]

The Band to show is not in the composite. Pick one you selected under Bands or Indices, or valid_count. true_color needs red, green and blue. false_color needs nir, red and green.

The map looks blocky compared with the GeoTIFF

The overlay is downsampled to at most 2048 px on its long side to keep the dashboard light. The GeoTIFF is full resolution.

Colours look washed out, or different between runs

The colour scale stretches from the 2nd to the 98th percentile of each run's values, so the same colour can mean different values in two runs. Read values from the legend. True/false colour is stretched channel by channel, which can shift the colour balance.

Developing

CI says the generated files differ from the committed ones

Recompile with ./dev/recompile.sh --update and commit the changes in ecoscope-workflows-cloud-mask-composite-images-workflow/.

CI says VERSION.yaml must be greater than main's

Every change needs a new version. --update bumps it: the minor number when the run form is unchanged, the major number when it changed.

A test case fails in CI but works locally

The CI reads each data source's credentials from the repository's GitHub secrets, named in .github/workflows/test.yml. Add the missing ones under Settings → Secrets and variables → Actions.
